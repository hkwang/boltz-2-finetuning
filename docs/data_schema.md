# Data organization

How Mac1 data is laid out on disk and how the tables link. There is no database or formal schema: everything is a flat CSV
or a per-ID file, joined on `pdb_id` (4-character, upper case) and, for ligands, on the CCD component code. Dataset provenance
and caveats are in [`datasets.md`](datasets.md); this file only describes structure. Update it when a table or directory changes.

## Directory layout

| Path | Content | Written by |
|---|---|---|
| `data/raw/mac1/` | Downloaded supplements and PMC XML, as published | `experiments/build_mac1_dataset.py` |
| `data/raw/ccd/{CODE}.cif` | RCSB chemical component CIFs for every ligand code in the structures (292 files) | `experiments/match_mac1_ligands.py` |
| `data/structures/mac1/{PDB_ID}.cif` | RCSB mmCIFs, one per Mac1 entry (603) | `experiments/fetch_mac1_structures.py` |
| `data/processed/*.csv` | Derived tables (below) | `experiments/*.py` |
| `data/processed/mac1_mols/{CODE}.pkl` | Boltz CCD-format RDKit molecules for the 191 ligand codes missing from `~/.cache/boltz/mols` | `experiments/build_mac1_mols.py` |
| `data/processed/boltz_inputs/` | Boltz-2 training inputs: `structures/{id}.npz`, `constraints/{id}.npz`, `mols/{id}.pkl`, `records/{id}.json`, `manifest.json` (2,949 records, 47 MB) | `experiments/build_mac1_boltz_inputs.py` |
| `data/processed/mac1_cofold/inputs/` | Boltz input YAMLs for the zero-shot co-folding run | `experiments/prepare_mac1_cofold.py` |
| `experiments/results/` | Run outputs and summaries | job scripts |

Nothing is written to `~/.cache/boltz`. Raw files are never edited; every processed file is regenerated by the script named above.

## Joins and conventions

- **Structure to label:** `mac1_structures.csv.pdb_id` = `mac1_splits.csv.pdb_id` = `mac1_ligands.pdb_id`. `mac1_structures.affinity_split` is the split copied from `mac1_splits.csv` (empty if the entry has no IC50).
- **Ligand to molecule:** each code in `mac1_ligands.ligand_codes` resolves to `~/.cache/boltz/mols/{CODE}.pkl` if `in_boltz_ccd` is true, otherwise to `data/processed/mac1_mols/{CODE}.pkl`.
- **Training use:** the diffusion head trains on `mac1_structures.diffusion_train == True` (557 entries; the 46 val/test entries are excluded); the affinity head trains on `mac1_splits.split == "train"` plus `mac1_nonhit_records.csv` (binary label 0, structure loss off, no pose) and the `mac1_fragment_hit_records.csv` rows with `affinity_binary` = 1 and `split` = train (binary label 1). Val/test stay held out for both heads.
- **Units:** `ic50_uM` is micromolar as published. `ic50_qualifier == ">"` means censored (the value is a lower bound). `ki_uM` is only filled where the source reports it. Boltz predicts `affinity_pred_value` as log10(IC50 in µM).
- **Dates:** ISO `YYYY-MM-DD`. `pre_cutoff` marks entries released before the Boltz-2 training cutoff (2023-06-30), which Boltz-2 may have seen.
- **Booleans:** `True`/`False` strings in CSV. Missing numbers are empty cells.
- **Splits:** assigned per PDB entry by `src/boltz2_finetuning/splits.py` (seeded, cluster-based so similar ligands share a split); regenerate with `experiments/make_mac1_splits.py`, do not edit by hand.

## Molecule files (`mac1_mols/{CODE}.pkl`)

Pickled RDKit `Mol` in the same format as the Boltz CCD cache: heavy atoms in component-CIF order, atom props `name` (matches the mmCIF atom names), `alt_name`, `leaving_atom`; 10 ETKDG conformers; mol props `MOL_NAME`, `symmetries` and the constraint arrays (`pb_*`, `chiral_*`, `stereo_bond_*`, `aromatic_5/6_ring_index`, `planar_double_bond_index`) as hex-pickled numpy arrays.
Built and checked against cached molecules by `src/boltz2_finetuning/ccd.py` and `testing/test_ccd.py` (names, bonds, chirality tags, symmetries as sets, reference chiral centres and ring constraints agree).
Checked against the cached molecules that have a downloaded component CIF (100-109 codes): atom names, leaving-atom flags, charges and chirality tags match, and symmetries match as sets (the order differs).

- **Chiral constraints, checked against the deposited coordinates.** For every ligand copy in the 603 structures, the signed volume of each constraint's atom quadruple was compared with its stored handedness (the same dihedral test Boltz's `ChiralAtomPotential` uses). Reference centres: built 98.3% satisfied (451/459), cached 96.8% (242/250). Non-reference quadruples: built 83.3% (105/126), cached 40.9% (38/93). The cache's non-reference ordering is therefore inconsistent with real structures, and the built molecules are the better set. The remaining violations are one RBB copy in 5SRM (the two protomers model opposite stereo; flagged by `model_copies_consistent`) and the phosphorus centres of AR6 in 7TWT/7TWV/7TWW/7TX0/7TX1/8SH8. Component stereo agrees with the stereo re-derived from the models for all matched pairs (`model_stereo_agrees_with_component`), so no rebuild was needed.
- **Distance bounds are not a bond-length effect.** Bonded pairs agree to ~0.03 A. The differences are in 1-3 and 1-4 pairs, mostly the 1-3 lower bound. They are not rotamer or atom-order effects either: shuffling atom order, kekulizing, adding Hs, dropping conformers and SMILES round-trips do not reproduce the cached values, and recomputing on the cached molecule itself differs from the cache for all 109 codes (angle mask too). The cache was generated by an unknown, different procedure, and I could not reproduce it.
  Against the deposited models the two sets are about equally good: fraction of ligand distances inside the bounds (+-0.1 A) is 0.95/0.93/0.947/0.952/0.983 (cached) vs 0.95/0.94/0.968/0.953/0.986 (built) for 1/2/3/4/5+ bonds apart. Against the cached molecules' own conformers, 1-3 pairs are inside the built bounds 90.6% of the time vs 84.0% for the cached bounds. Built bounds are kept.
- Where the bounds are used: only in `rdkit_bounds` steering potentials (`model/potentials/potentials.py`, inference-time guidance). No training loss reads them (grep of `model/`).

## Boltz training inputs (`boltz_inputs/`)

Built by `src/boltz2_finetuning/records.py` and `experiments/build_mac1_boltz_inputs.py`; checked by `testing/test_boltz_inputs.py` (manifest/table/file agreement, affinity ligand = labelled ligand, held-out entries never train the diffusion head, and 40 sampled records run through Boltz-2's own `Boltz2Tokenizer` + `Boltz2Featurizer`). `mac1_training_records.csv` is the join table: one row per record, and the only place labels live (records carry only `AffinityInfo`).

- **Crystal records (603 `id` = PDB ID):** `parse_mmcif` on the asymmetric unit (`use_assembly=False`; assembly 1 omits the modelled ligand in 5S3W), with the built molecules passed as extra mols. Protein `msa_id = -1`. Residue constraints come from `parse_mmcif`. Interfaces are computed (the `compute_interfaces` shadowing bug did not occur because the mmcif_with_constraints parser is used).
- **Negative records (2,346 `mac1_nonhit_NNNN`):** Boltz's own sequence+SMILES path (`parse_boltz_schema`), so the structure is a ligand conformer placed at zero coordinates, not a pose; protein sequence = apo 7KQO chain A. `structure_loss_weight` = 0.
- **Affinity ligand:** `AffinityInfo(chain_id, mw)`; mw is RDKit `MolWt` of the heavy-atom molecule (Boltz's own formula). One ligand per record. IC50 pairs use the first matched code in `mac1_ligands.csv` (the 29 racemic pairs with two enantiomer codes therefore use the first-listed one, 'closest-stereo' selection not implemented). Binary positives use the chain and code from `mac1_fragment_hit_records.csv`.
- **Label precedence:** IC50 > binary. 169 IC50 records (124 train, 21 val, 24 test); 174 binary-positive crystal records (train) + 2 `held_out_similar` (leave out); 2,346 negatives (train); 258 crystal records with no affinity label (structure only), including 7HFU and 7HFX whose table SMILES do not match the deposited ligand.
- **Unused crystal records:** val/test crystals have `diffusion_train` False and `structure_loss_weight` 0. 557 crystals train the diffusion head.
- **Failures:** `mac1_nonhit_1487` (an N-acetyl bicyclic amine) is dropped: RDKit cannot embed it (`Failed to compute 3D conformer`).
- `log10_ic50_uM` is log10 of the table `ic50_uM`; `ic50_qualifier` `>` means the value is a lower bound (censored). Four PNAS entries (5SPD, 5SQ3, 5SQD, 5SQO) report two IC50 values, one per stereoisomer; they have no single `ic50_uM`, so they are not in `mac1_splits.csv` and their crystals carry no IC50 label.
